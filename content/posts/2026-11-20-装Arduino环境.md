## 今天要做什么

搭建Arduino环境并成功运行呼吸灯效果

## 实际做了什么

###1.安装Arduino CLI  
```text
https://downloads.arduino.cc/arduino-cli/arduino-cli_latest_Windows_64bit.zip
```  
###2.建立CLI配置文件  

系统默认数据目录在受限环境下会报 `Access is denied`，因此需要指定可写目录，并注册 ESP32 板卡索引。

```yaml
directories:
  data: <可写的数据目录>
  downloads: <可写的下载目录>
  user: <可写的用户库目录>
board_manager:
  additional_urls:
    - https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

之后所有命令都带上 `--config-file <配置文件路径>`。  

###3.更新索引并安装AVR平台

添加 ESP32 索引地址后必须执行一次索引更新，否则 CLI 发现不到该平台。

```powershell
arduino-cli --config-file <配置> core update-index
```

成功时会下载 `package_index.json`、`library_index.json` 与 `package_esp32_index.json`。

AVR 平台适合 Uno / Nano，体积小、下载快，通常一两分钟完成（约 71 MB）。

```powershell
arduino-cli --config-file <配置> core install arduino:avr
```

###4.安装ESP32平台

```powershell
arduino-cli --config-file <配置> core install esp32:esp32
```

耗时差异很大：直连 GitHub 约 26 KB/s，按此速度需要数小时以上；使用加速代理实测 0.6~1.4 MB/s，约 30~50 分钟。

> 开代理的方法：在下载地址前拼接加速域，如 `https://gh-proxy.com/<原始地址>`，即可把 GitHub 下载转到代理通道。

### 常用维护命令

```powershell
arduino-cli --config-file <配置> core update-index      # 刷新索引
arduino-cli --config-file <配置> core upgrade            # 升级已装平台
arduino-cli --config-file <配置> core uninstall esp32:esp32   # 卸载重装时使用
arduino-cli --config-file <配置> core search esp32       # 确认平台可被检索到
```

###5.编写呼吸灯代码

```cpp
int duty = (long)level * level / PWM_MAX;  // 等效 gamma≈2.0
```

`setup()` 初始化 PWM 并熄灭 LED；`loop()` 先渐亮再渐暗，结束后自动进入下一轮，每轮末尾显式写入最大值与 0 补齐端点。

周期 ≈ `2 × 255 ÷ BREATH_STEP × STEP_DELAY_MS`，默认约 **2.56 秒**。

###6.安装CH340串口驱动

```powershell
Start-Process "CH341SER.EXE" -ArgumentList "-s","-d<目标目录>" -Wait

# 2. 以管理员身份安装并重新扫描
pnputil /add-driver "<目标目录>\CH341SER.INF" /install
pnputil /scan-devices
```

安装成功后设备名变为 `USB-SERIAL CH340 (COMx)`。这一步需要管理员权限，普通会话会弹 UAC 授权框。

## 遇到的问题 & 怎么解决的

> 现象：串口监视器一直刷乱码  
> 我猜的原因：板子坏了  
> 试了什么：换了一根线、换了一个 USB 口  
> 真正的原因：串口波特率设成了 9600，但代码里是 115200

改过来之后第一行打印正常输出了。
>现象：设备管理器`USB Serial`错误码28  
>我猜的原因:设备没有安装好
>试了什么：重新安装设备，调试
>真正的原因:CH340驱动未安装，安装CH340驱动

## 我理解的关键概念

`setup()` 只跑一次，`loop()` 一直循环。相当于"开机准备"和"上班干活"。  
PWM 占空比通过快速开关调节平均电压，8 位分辨率对应 0~255
CH340:常见的 USB 转串口芯片，需单独安装驱动才能在系统中生成串口  

## 最佳实践

要让整套流程一次成功，建议按以下顺序执行：

1. **先装工具，再插板子**：先完成 CLI、配置文件和两个平台核心安装，最后再插开发板，避免中途驱动与端口问题干扰判断。
2. **固定两个目录**：数据目录与构建目录都放在确定可写的位置，并把配置写进 yaml，后续命令无需重复调整。
3. **先编译后烧录**：不接板子也能验证代码，编译不通过绝不要进入烧录环节，可节省大量时间。
4. **版本固定**：记录 CLI 1.6.0、AVR 1.8.8、ESP32 3.3.12，避免不同版本接口差异（如 ESP32 Core 2.x 与 3.x 的 LEDC 接口不同）。
5. **下载用单实例 + 断点续传**：大文件下载中断是常态，续传比重下更稳；严禁并发写同一文件。
6. **驱动先确认再烧录**：看到 `USB-SERIAL CH340 (COMx)` 才继续，错误码 28 时不要浪费时间重试上传。
7. **烧录前固定进入下载模式**：即使自动下载电路正常，手动 BOOT + EN 也能排除大部分连接失败。
8. **用烧录日志判断成败**：只认 `Hash of data verified` 与退出码 0，不要靠"看起来没报错"。
9. **参数改一处就好**：调整呼吸快慢只改 `BREATH_STEP` 与 `STEP_DELAY_MS`，其余保持不动，便于复现。
10. **把环境文档纳入版本库**：换机器或协作时可直接照文档重建环境。  

## 总结

本项目记录了在 Trae IDE 中不依赖 Arduino IDE、仅用命令行工具`arduino-cli` 完成 LED 呼吸灯开发的完整流程：先安装 Arduino CLI 并配置可写的数据目录和构建目录，再安装 AVR 与 ESP32 平台核心、装好 CH340 串口驱动，然后编写基于 PWM 的呼吸灯代码，用平方曲线校正亮度，使 LED 在约 2.56 秒内完成 灭→最亮→灭 的平滑循环，最后编译、烧录到 ESP32 或 Uno/Nano 并进行真机验证，实现“编写—编译—烧录—运行”的全流程可复现。
