## 今天要做什么

通过手机WIFI网页使得板载LED灯亮

##硬件条件  

开发板 : ESP32-DevKit-32E 或同类 ESP32 开发板 
USB 数据线 : 必须支持数据传输，不能是仅充电线 
手机热点: 必须为 **2.4 GHz**；iPhone 需开启「最大兼容性」

 
## 实际做了什么
###  建立工程与配置热点

文件夹名必须与 `.ino` 同名（`ESP32_WebLED/ESP32_WebLED.ino`）。文件顶部集中放置配置：

```cpp
const char* WIFI_SSID     = "手机热点名称";
const char* WIFI_PASSWORD = "热点密码";

#define LED_PIN 2
#define LED_ACTIVE_LOW 0   // 1 = 低电平点亮（部分开发板）
```  
###  以 STA 模式连接热点

```cpp
WiFi.mode(WIFI_STA);
WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

unsigned long start = millis();
while (WiFi.status() != WL_CONNECTED && millis() - start < 20000) {
  delay(500);
  Serial.print(".");
}
```  
- 成功后打印 `WiFi.localIP()`，这就是手机要访问的地址
- 失败提示会明确指出「检查名称、密码，热点需为 2.4 GHz」  
###  搭建 HTTP 服务器

```cpp
WebServer server(80);

server.on("/", handleRoot);   // 首页：显示状态与按钮
server.on("/on", handleOn);   // 点亮
server.on("/off", handleOff); // 熄灭
server.begin();
```  
处理函数用 303 跳回首页，保证页面状态刷新：

```cpp
void handleOn() {
  ledOn = true;
  applyLed();
  server.sendHeader("Location", "/");
  server.send(303, "text/plain", "");
}
```  
###  生成手机端页面

页面由 `buildPage()` 拼接，包含 `viewport` 适配手机宽度、两个大按钮和当前状态文字。为避免占用 RAM，固定文本用 `F()` 宏存放在 Flash：

```cpp
html += F("<meta name='viewport' content='width=device-width,initial-scale=1'>");
html += F("<a class='on' href='/on'>点 亮</a>");
html += F("<a class='off' href='/off'>熄 灭</a>");
```    
###  获取 IP 并操作

读取串口（115200，UTF-8 解码）可看到：

```text
rst:0x1 (POWERON_RESET),boot:0x13 (SPI_FAST_FLASH_BOOT)
...
正在连接热点: (热点名字)
....
连接成功
请在手机浏览器打开:（网址）
网页服务器已启动（端口 80）
```

## 遇到的问题 & 怎么解决的

问题：无法按动ESP32上的boot键和EN键
解决方法：降低上传波特率，波特率 921600 下复位握手窗口太窄；改成 115200 后，`arduino-cli` 自带的 DTR/RTS 自动复位就能稳定把芯片带进下载模式

## 我理解的关键概念

DTR / RTS:串口控制信号，用于自动复位并触发下载模式
上传波特率：921600 或 115200，过低速时握手更稳定
2.4 GHz 限制:ESP32 不支持 5 GHz 热点

### 最佳实践

1. **先编译后烧录**：不接板子也能验证代码，编译不过绝不进入烧录环节。
2. **上传固定用 115200**：本项目实测 921600 易触发 `Wrong boot mode`，115200 一次成功。
3. **改完代码先保存**：编辑器缓冲区未落盘时，编译的是旧文件，极易误判为「代码没生效」。
4. **串口读取要设 UTF-8**：否则中文提示全部变成问号，难以定位问题。
5. **热点必须 2.4 GHz**：ESP32 不支持 5 GHz，这是连接失败最常见的原因。
6. **用串口日志判断成败**：认 `连接成功` 与 `http://<IP>` 两行输出，不靠猜。
7. **IP 会变化**：每次重连热点后重新读串口，不要长期使用旧地址。
8. **页面文本放 Flash**：用 `F()` 包裹固定 HTML，节省有限的 RAM。  

##  总结

本项目用 Arduino 框架让 ESP32-DevKit-32E 连接手机 2.4 GHz 热点，并内置一个 HTTP 网页服务器；手机浏览器访问串口打印的 IP 即可控制 GPIO2 板载灯的亮灭。整个流程在 Trae 中通过 `arduino-cli` 完成编译与烧录，其中把上传波特率改为 115200 后实现了免按键烧录，同时解决了热点频段、代码保存和串口编码等几个常见问题，最终可稳定运行。
